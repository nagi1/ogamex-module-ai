# What this source is good for

The definition of a **safety probe** — the reactive/defensive use of a probe to detect a ninja or an
ACS defend before committing — split by whether the universe allows ACS.

## Position stated (verbatim, trimmed)

> There are two explanations for a safety probe depending on whether or not a universe allows ACS.

**Non-ACS universe:** "a probe is timed to arrive at a planet in front of an attacking fleet so that a
ninja attempt may be detected. A tradeoff exists between sending the probe late enough to detect a
defending fleet's arrival and allowing enough time for an attacking fleet to be recalled."

**ACS universe:** "probes can be joined onto attack fleets using the alliance combat system, slowing
your fleet and allowing time to send another probe on its own in an espionage mission to the planet.
If an ACS defend fleet has been sent, this probe will show the fleet in orbit. If a fleet has been
slowed with ACS probes there will be enough time for it to be recalled."

## Worked example (verbatim)

> An attack lands at 23:00 server time. A safety probe is sent to arrive at 23:01 server time. The
> attacking fleet can be slowed by adding a probe to delay the time to 23:10 server time. Now any ACS
> defend (which will add ships to the safety ESP report) will show up and allow the time to recall.

**ANECDOTAL (example timings):** 23:00 / 23:01 / 23:10 are the page's illustrative numbers, not
thresholds.

## Numbers

- Only the example clock times above. **No ratios, costs or distance thresholds** are stated.

## Limitations

- **CONTESTED as mechanics:** that probes joined to an attack fleet slow it, that an ACS defend shows
  in the espionage report, and the "tradeoff" window are community statements. Confirming them needs
  the official Gameforge ACS/espionage rules or the host implementation.
- The page assumes ACS exists as a universe option; on a non-ACS ruleset only the first explanation
  applies. Recorded as a **ruleset limitation**, not as a rule.
